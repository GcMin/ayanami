# 架构决策记录

本文件汇总已接受的决策。改变已接受决策时，不直接覆写历史结论；新增 ADR，记录新背景、迁移影响和替代关系。

## ADR-001：产品是纯本地阅读器

状态：接受  
日期：2026-08-01

决定：不建设应用账号、自有后端、云同步、OCR、翻译或 AI 模型。网络仅服务于漫画源和第三方内容。

影响：所有用户状态保存在设备本地。

## ADR-002：Flutter 作为客户端 UI 技术栈

状态：接受

决定：当前 Android 客户端继续使用 Flutter/Dart。

影响：UI、应用层和领域层保持 Dart 实现；平台能力通过适配器接入。

## ADR-003：JavaScript 源而非 APK 扩展

状态：接受

决定：漫画源只能使用受限 JavaScript 与数据资源，不加载 APK、DEX、JAR、动态库、WebAssembly 或原生插件。

影响：所有源必须遵守统一 Source SDK 和 Host API。

## ADR-004：开发阶段优先单文件 `.js`

状态：接受

决定：Android MVP 优先实现单文件 `.js` 源安装与运行。`.msrc` 作为后续正式分发格式，不作为当前纵向闭环的前置阻塞。

替代：原 ADR-004 中“开发 `.js`，正式 `.msrc`”仍保留长期方向，但实施顺序调整。

## ADR-005：无内容站登录能力

状态：接受

决定：不提供账号输入、WebView 登录、验证码或认证自动化。

## ADR-006：本地 SQLite 与应用私有文件

状态：接受

决定：SQLite 保存结构化状态，应用私有目录保存源文件、图片缓存和下载文件。

## ADR-007：Android 为当前唯一 MVP 验收平台

状态：接受  
日期：2026-08-20

决定：当前产品开发与 MVP 验收以 Android 10+ 为主。iOS 从当前验收范围移出，只保留未来兼容可能。

理由：当前仓库和真实调试链路都集中在 Android。先同时维护 Android/iOS 会扩大运行时、后台下载和分发问题，却不能提高当前产品闭环验证效率。

影响：路线图、测试矩阵、后台下载方案与发布流程均以 Android 为准。

## ADR-008：不自动合并同名漫画

状态：接受

决定：同名搜索结果按来源独立展示；首版不自动判断为同一作品。

## ADR-009：平台后台任务只是执行器

状态：接受

决定：下载任务状态保存在本地数据库，Android WorkManager 负责执行。

## ADR-010：无内置公共源市场

状态：接受

决定：应用不运营、推荐或默认配置公共漫画源目录。

## ADR-011：搜索结果按来源回路由

状态：接受

决定：每项结果由 `(sourceId, sourceMangaId)` 唯一标识；点击后只调用产生该结果的同一漫画源。

## ADR-012：漫画源是独立一级入口

状态：被 ADR-016 扩展

原决定：源管理不属于设置页。

该结论继续有效，但一级导航结构由 ADR-016 重新明确。

## ADR-013：书架属于宿主本地领域

状态：接受

决定：漫画详情页“加入书架”由宿主本地写入完成，不要求源实现收藏接口。

## ADR-014：阅读缓存与正式下载分离

状态：接受

决定：阅读时预加载产生的缓存不等同于正式离线下载。

## ADR-015：当前章节允许积极预加载

状态：接受

决定：可根据设置预加载当前章节页面，以减少同章节阅读等待。

## ADR-016：首页固定为“书架 / 漫画源 / 设置”三入口

状态：接受  
日期：2026-08-20

决定：应用首页使用三个一级入口：

```text
书架 | 漫画源 | 设置
```

并规定：

- 默认进入书架；
- “发现/搜索”不再作为独立一级导航；
- 漫画源页同时承担源管理和内容发现；
- 设置页不重复提供漫画源管理入口。

理由：用户的主任务实际上只有“读已收藏漫画”“找漫画”“调整应用”。把源管理、源浏览和搜索割裂成多个一级页面会增加导航成本。

影响：现有 UI 后续重构时应围绕三个 Tab 建立 `AppShell`。

## ADR-017：漫画源页同时承担管理和发现

状态：接受  
日期：2026-08-20

决定：`SourcesTab` 内部分成两个逻辑区域：

```text
Content Discovery
Source Management
```

用户可先选某个源浏览，也可对全部已启用源执行聚合搜索。

影响：`discovery` 不再作为独立一级 feature；应用层仍保留 `SearchAcrossSources` 用例。

## ADR-018：当前 `flutter_js` 是过渡 Runtime Adapter

状态：接受  
日期：2026-08-20

背景：仓库已经存在基于 `flutter_js` 的真实 JS 漫画源搜索、详情和章节原型，而旧文档仍把 JavaScript 源描述为完全未实现。

决定：

- 承认现有 `flutter_js` 原型是当前实现；
- 不立即为了“架构纯洁”重写整个运行时；
- 首先把它封装到 `SourceRuntimeAdapter` 后面；
- Source SDK 与领域层不得依赖 `flutter_js`；
- 后续若需要 QuickJS C ABI，可在不改变上层业务契约的情况下替换。

理由：先完成可验收产品闭环，再替换底层运行时，能避免一次性重写 UI、源 SDK、沙箱和存储四个方向。

影响：运行时安全能力仍需补齐，包括超时、内存限制、Host API 白名单、域名限制和错误隔离。

## ADR-019：`.msrc` 延后到源插件 MVP 之后

状态：接受  
日期：2026-08-20

决定：MVP 首先完成 `.js` 的本地/HTTPS 安装、Manifest、权限确认、启停和更新基本能力。`.msrc`、签名和回滚放入安全增强里程碑。

理由：单文件 JS 足以验证插件生态的核心接口，包签名不应阻塞首页、搜索、详情、书架和阅读闭环。

## 待验证技术问题

- 生产版 JS Runtime 最终继续使用现有引擎还是切换 QuickJS C ABI；
- 是否需要线程之外的独立进程隔离；
- SQLite/Drift 迁移时如何平滑接管现有偏好数据；
- 长章节大图预加载在低内存 Android 设备上的峰值；
- `.msrc` 签名密钥轮换与撤销格式。
