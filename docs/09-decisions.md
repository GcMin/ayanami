# 架构决策记录

本文件汇总已接受的决策。改变已接受决策时，不直接覆写历史结论；新增 ADR，记录新背景、迁移影响和替代关系。

## ADR-001：产品是纯本地阅读器

状态：接受  
日期：2026-08-01

决定：不建设应用账号、自有后端、云同步、OCR、翻译或 AI 模型。网络仅服务于源包、第三方内容元数据和图片。

理由：用户明确要求软件只承担阅读器职责，降低隐私、运营成本和系统复杂度。

影响：所有用户状态存于设备；卸载或设备损坏可能导致数据丢失，除非未来新增用户主动导出。

## ADR-002：Flutter + 原生 QuickJS

状态：接受

决定：共享 UI、用例和领域层使用 Flutter/Dart；QuickJS 通过窄 C ABI 和 Dart FFI 接入 Android/iOS。

理由：UI 跨平台复用，同时避免在 WebView 中向不可信网页暴露 JavaScript bridge。Flutter 官方支持通过 FFI 调用原生 C API，参见 [Flutter C interop](https://docs.flutter.dev/platform-integration/android/c-interop)。

影响：需要维护原生构建、线程/进程隔离和 C ABI 测试。

## ADR-003：JavaScript 源而非 APK 扩展

状态：接受

决定：源只能是受限 JavaScript 与数据资源，不加载 APK、DEX、JAR、动态库、WebAssembly 或原生插件。

理由：统一 Android/iOS 源契约，缩小权限，并避免源拥有完整应用进程能力。

影响：复杂站点只能使用 Host API 能力；需要浏览器自动化、登录或任意原生能力的源不受支持。

## ADR-004：开发 `.js`，正式 `.msrc`

状态：接受

决定：开发者模式允许单文件 `.js`；正式分发用 `.msrc` 封装 Manifest、脚本、资源和签名。

理由：单文件便于调试，包格式便于版本、完整性、权限差异和签名验证。

影响：宿主必须实现安全解包、规范化哈希、升级与回滚。

## ADR-005：无内容站登录能力

状态：接受

决定：不提供账号输入、WebView 登录、验证码或认证自动化。HTTP 客户端可维护源域名产生的隔离 Cookie，但没有交互式凭据流程。

理由：保持纯阅读器范围并避免凭据、反爬和访问控制风险。

影响：要求登录或付费访问的源不兼容；不得通过源脚本自行实现登录 UI。

## ADR-006：本地 SQLite 与应用私有文件

状态：接受

决定：SQLite 保存结构化状态，应用私有目录保存源包、图片和下载文件。数据库是任务状态事实来源。

理由：支持事务、查询、迁移和进程恢复；避免公共存储权限与路径风险。

影响：必须实现数据库/文件对账和原子写入。

## ADR-007：双发行能力集

状态：接受

决定：完整 JS 源能力和商店受限能力使用不同的编译期 capability。iOS App Store 构建默认不含用户下载并执行 JS 源的入口。

理由：Apple 对下载并执行改变功能的代码有限制；Google Play 对运行时解释代码也要求不得产生政策违规能力。

影响：各渠道功能不完全一致；市场文案、测试矩阵和二进制均必须诚实反映能力。

## ADR-008：不自动合并同名漫画

状态：接受

决定：首版同名搜索结果始终按来源独立展示；用户可手动关联为同一书架作品。

理由：标题、语言和版本不足以可靠判定作品身份。

影响：跨源体验多一步手动操作，但避免误合并和进度错配。

## ADR-009：平台后台任务只是执行器

状态：接受

决定：下载任务与进度持久化在 SQLite；WorkManager 和 background URLSession 负责平台执行，重启时进行协调。

理由：平台可能延迟、停止或重建任务，不能让 UI 状态只存在平台回调内。Android 官方推荐 WorkManager 处理持久后台工作；iOS background URLSession 支持应用挂起时继续下载，参见 [Android WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent) 与 [Apple background downloads](https://developer.apple.com/documentation/foundation/downloading-files-in-the-background)。

影响：所有 Worker/回调必须幂等，需要三方状态对账。

## ADR-010：无内置公共源市场

状态：接受

决定：应用不运营、推荐或默认配置公共漫画源目录；用户主动选择本地文件或 HTTPS 索引。

理由：保持工具属性，减少内容授权、维护和信任背书风险。

影响：首次使用需要导入测试源或用户自备源；内置测试源只能访问项目控制的合法夹具。

## ADR-011：搜索结果按来源回路由

状态：接受

决定：发现页把漫画名称并发传给所有已安装且已启用的 JS 源。每项结果由 `(sourceId, sourceMangaId)` 唯一标识；点击结果后，宿主只调用产生该结果的同一源的 `getMangaDetails` 和 `getChapters`。

理由：标题和 URL 都不足以识别源及作品；重新聚合搜索可能得到不同结果，也可能错误地由其他源解释源内字段。

影响：搜索结果模型和详情路由必须保留 `sourceId`、源版本与 `MangaRef` 快照。源被禁用、删除或升级导致引用失效时，详情页必须给出可恢复错误，不得静默切换来源。

## ADR-012：JS 源使用独立入口并从 URL 安装本地副本

状态：接受

决定：主界面新增“JS 源”按钮并与“设置”按钮并列，源管理不再属于设置页。用户可在独立源页面输入 HTTPS URL 下载单个 `.js`；应用完成临时下载、校验、权限确认后保存并加载本地不可变副本。

理由：源安装、权限和运行错误是独立业务领域，不应混入普通偏好设置。运行固定本地副本可避免远端内容未经确认变化，使版本、哈希、回滚和安全审计具备稳定依据。

影响：需要独立源管理路由和 `DownloadSourceFromUrl` 用例。URL 不能被当作运行时动态模块地址；检查更新和安装更新必须由用户主动触发并重新确认。

## ADR-013：详情本地入架，书架按作品批量创建下载计划

状态：接受

决定：JS 源漫画详情页提供“添加到书架”按钮，宿主以 `(sourceId, sourceMangaId)` 幂等写入本地书架，不要求源实现收藏接口。书架支持选择多部漫画后创建一个下载批次，默认下载各漫画尚未完成的章节。

理由：书架是跨源、本地持久的用户状态，不应受源 API 是否提供收藏能力影响。下载批次为用户提供统一确认和控制，同时章节级任务仍能独立恢复和失败隔离。

影响：需要 `DownloadBatch` 汇总实体、稳定的 `libraryEntryId` 选择状态和批次确认页。批量操作不能用标题或列表索引标识作品，也不能因一个来源失败而放弃全部选择。

## ADR-014：章节后续页使用有限滑动缓存，页面适配可分级持久化

状态：接受

决定：在线阅读时默认自动缓存当前章节后续 5 页，允许关闭或设置 1–20 页，且不自动跨章节。页面适配支持原始尺寸、适应宽度、适应高度、适应屏幕和智能适应，并按“本次会话 > 当前漫画 > 全局默认”保存。

理由：有限滑动窗口可以改善连续阅读，又避免打开章节就下载全部页面；将缓存与正式下载分开可维持清晰的离线语义。分级保存适配偏好既支持临时查看特殊页面，也支持作品和全局习惯。

影响：需要独立的内存预加载与磁盘缓存协调器、缓存 LRU 元数据、计量网络约束以及作品级 `reader_preference`。缓存命中可以被正式下载复用，但不能提前把章节标记为已下载。

## ADR-015：当前章节页面全量预加载

状态：接受

决定：用户打开章节后，在后台按页面清单预加载当前章节全部图片；阅读器实时刷新缓存清单，已落盘页面优先使用本地文件。该缓存仍与正式下载分离，不能将章节自动标记为正式离线完成。

理由：当前漫蛙章节图片请求包含解密和网络延迟，有限后续页窗口会导致用户在同一章节内频繁等待。全量预加载优先保证章节内连续阅读体验。

影响：章节较长时会产生较多网络与存储开销；用户可在设置中关闭章节全量预加载，正式下载仍必须由用户主动触发。

## 待验证但未改变范围的技术问题

- QuickJS 使用线程隔离是否足够，还是生产版必须使用独立进程；
- iOS 后台下载与短期签名图片 URL 的恢复体验；
- `.msrc` 签名密钥轮换和撤销数据格式；
- 大图解码库在低内存设备上的峰值与裁边性能。

这些问题由 M0/M1 原型给出证据后形成新的 ADR。
