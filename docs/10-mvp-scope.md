# MVP 范围决策

> 说明：本次已新增漫蛙 JS 源的发现、搜索结果、详情与章节解析链路；本文中“暂未实现 JS 源”的历史说明仅适用于本次接入之前的 MVP 基线。

状态：开发中

当前 Android MVP 使用 Dart 固定测试内容适配器，不执行漫画源 JavaScript，也不实现 `.js`/`.msrc` 导入、QuickJS、网络源权限或签名验证。

固定测试内容只用于验证产品纵向闭环：

```text
搜索 -> 详情/章节 -> 书架 -> 阅读 -> 下载状态 -> 重启恢复 -> 离线阅读
```

保留 `ContentSourcePort` 这一层边界，后续接入源运行时时替换适配器，不让 UI 依赖 QuickJS 或源 SDK。首个 MVP 的持久化使用本地偏好作为过渡实现；SQLite/Drift、原子文件存储和平台后台下载属于后续 M0/M3 工作，不在本次范围内伪装成已完成能力。

明确的占位入口会向用户说明“漫画源 JS 暂未启用”，避免把固定测试内容误解为第三方源能力。

后续启用 JS 源时，发现与详情必须遵循 [JS 源发现与详情流程](11-source-discovery-flow.md)。本文只说明当前代码暂未实现该能力，不取消产品对 JS 源、聚合搜索和来源内详情路由的正式需求。

届时 JS 源采用与“设置”并列的独立按钮和页面，不放入设置页；该页面支持通过 HTTPS URL 下载、校验、确认并加载 `.js` 本地副本。当前 MVP 不实现这一入口。
