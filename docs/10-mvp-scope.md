# MVP 范围决策

状态：开发中  
日期：2026-08-20

## 1. 当前基线

当前仓库已经不是“纯固定 fixture、完全没有 JS 源”的阶段。

现有 Android 原型已经包含：

- Flutter 客户端；
- 固定测试漫画；
- `flutter_js` JS 执行能力；
- 漫蛙 JS 源适配器；
- 搜索、详情、章节解析链路；
- 基础书架、阅读器、缓存和本地状态。

因此后续文档和开发任务不得继续把“JS 源尚未启用”当作当前事实。

## 2. 当前 MVP 目标

本轮 MVP 的目标是把现有原型整理成真正可扩展的 Android 漫画阅读器：

```text
首页三 Tab
  -> 漫画源安装/管理
  -> 单源或多源搜索
  -> 漫画详情/章节
  -> 加入书架
  -> 阅读
  -> 本地保存进度
```

下载持久化作为紧随其后的阶段完成。

## 3. 首页

首页固定为：

```text
书架 | 漫画源 | 设置
```

要求：

- 启动默认进入书架；
- 不再提供独立一级“发现”页；
- 搜索和浏览进入“漫画源”；
- 源安装、启停和错误也进入“漫画源”；
- 设置只保存应用偏好。

## 4. JS 源 MVP

首阶段只要求单文件 `.js`：

- 本地导入；
- HTTPS URL 导入；
- Manifest；
- `sourceApiVersion`；
- 域名声明；
- 用户确认；
- 启用/禁用；
- 删除；
- 基础更新。

`.msrc`、签名和完整回滚不作为当前插件 MVP 的阻塞条件。

## 5. Runtime 策略

当前 `flutter_js` 保留作为过渡实现。

必须先建立：

```text
SourceRuntimeAdapter
```

UI 和应用层只依赖该接口。

后续如替换为 QuickJS 原生运行时，只替换基础设施实现，不修改搜索、详情、书架和阅读业务模型。

## 6. 当前不要求完成

- iOS；
- `.msrc` 正式签名生态；
- 云同步；
- OCR/AI 翻译；
- 内容站登录；
- 自动同作品合并；
- 桌面端。

## 7. MVP 验收

在 Android 真机完成：

1. 首页只有三个一级入口；
2. 从漫画源页添加一个 JS 源；
3. 启用该源；
4. 搜索漫画；
5. 打开详情与章节；
6. 加入书架；
7. 返回书架可见；
8. 打开章节阅读；
9. 重启应用后书架和进度仍存在；
10. JS 源异常不会让整个应用崩溃。
