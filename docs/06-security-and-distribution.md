# 安全与发行

## 1. 威胁模型

必须假设用户导入的源包、源仓库索引、远端 HTML/JSON、图片、重定向和错误信息全部不可信。

主要威胁：

- 源脚本无限循环、递归、内存耗尽或返回超大对象；
- SSRF 访问 localhost、局域网、云元数据地址或其他未声明域名；
- 重定向和 DNS rebinding 绕过域名校验；
- 路径穿越、ZIP bomb、文件名碰撞和恶意图片；
- 源升级静默增加权限或替换为恶意版本；
- 日志泄露 Cookie、Token、阅读内容或完整 URL 参数；
- JS 逃逸到原生 API、任意文件或其他源状态；
- 渠道构建隐藏完整能力以规避审核。

不在应用威胁模型内承诺解决：已 Root/Jailbreak 且攻击者控制系统、用户主动授予外部调试器完整进程访问、第三方源站本身的内容合法性和长期可用性。

## 2. 信任边界

```text
不可信
  .msrc/.js、仓库索引、HTTP 响应、图片、源返回对象
       |
       v
Package Verifier / Schema Validator / Network Policy / Image Decoder
       |
       v
受信任
  领域对象、数据库事务、应用文件路径、UI 状态
```

每次跨越边界都做验证，不能因为包已签名而跳过运行时校验。签名只回答“由谁发布、内容是否被修改”，不回答“脚本是否安全或合法”。

## 3. 沙箱要求

- 每个调用使用隔离 Context；源之间不共享 JS 全局对象。
- 原生层只暴露窄 Host API，不链接 QuickJS 标准库中的文件和系统命令能力。
- 使用内存上限、中断回调、调用总超时、返回体上限和日志配额。
- Host API 句柄不可序列化、不可跨调用保存。
- QuickJS 崩溃不得破坏数据库事务；首选隔离工作进程，若 MVP 使用线程隔离，必须将崩溃隔离列为发布前阻断项评估。
- 禁止 `eval`、`Function`、动态导入、WebAssembly 和原生模块。

QuickJS 提供运行时内存限制和中断处理器，可用于实现硬资源预算，参见 [QuickJS 官方文档](https://bellard.org/quickjs/quickjs.pdf)。

## 4. 网络策略

- 生产构建只允许 HTTPS；开发例外必须逐源、限时、显著展示。
- URL 解析使用标准库，不用字符串前缀判断主机。
- 每次请求、每个跳转和 DNS 解析后的所有地址均验证。
- 拒绝 loopback、私网、link-local、multicast、保留地址、IPv4-in-IPv6 和非 HTTP(S) 协议。
- 域名通配符只允许声明域的直接/递归子域，禁止公共后缀级通配。
- 限制方法、请求头、响应大小、重定向、速率和并发。
- TLS 错误不可由源忽略；证书例外不进入生产构建。

iOS 默认的 App Transport Security 要求安全连接；项目不设置全局任意加载例外，参见 [Apple ATS 文档](https://developer.apple.com/documentation/security/preventing-insecure-network-connections)。

## 5. 包签名与仓库

通过 URL 下载单个 `.js` 不等于信任该脚本。URL、TLS 和 SHA-256 只能保证本次下载与记录的一致性；未签名 `.js` 仍显示为 `unsigned`，必须经过权限确认。应用运行已安装的本地副本，不直接执行 URL 当前内容。

### 5.1 签名状态

```text
trusted     由用户信任的密钥签名且验证通过
valid       签名有效，但密钥未加入信任列表
unsigned    无签名
invalid     声明签名但验证失败
revoked     密钥或版本已撤销
```

`invalid` 和 `revoked` 默认拒绝安装。`unsigned` 只在完整版中通过明确风险确认安装。商店能力集可完全禁用未签名源。

### 5.2 建议算法

- 包摘要：SHA-256；
- 签名：Ed25519；
- `signature.json` 包含算法、密钥 ID、规范化包摘要和签名值；
- 公钥信任由用户或随应用发布的信任列表管理；
- 密钥轮换与撤销记录必须是签名数据，不能只靠普通 HTTP 文本。

### 5.3 仓库索引

仓库仅列出包元数据、版本、下载 URL、SHA-256 和签名信息。应用不执行仓库返回的脚本片段，不允许索引修改 UI，也不自动安装更新。

## 6. 权限与升级

安装确认展示：

- 精确域名及通配符；
- `network`、`cookies`、`sourceStorage` 等权限；
- 包签名状态和发布密钥；
- 从旧版本新增/删除的权限；
- 源能看到用户搜索词、IP 地址和请求时间的提示。

任何权限扩大、签名密钥变化或主版本跳跃都必须重新确认。禁用源立即阻止新的 JS 调用与网络请求；已经提交的平台图片下载按用户选择继续或暂停。

## 7. 本地数据安全

- 数据库存储在应用沙箱，不使用公共外部存储作为主数据目录。
- 源存储按 `sourceId` 隔离；Cookie 不进入通用日志和导出。
- 诊断导出默认删除查询参数、请求头、Cookie、响应正文、文件路径中的用户信息。
- Android 备份与 iOS 备份策略显式配置；下载的大体积可再获取内容默认排除系统云备份，书架数据库是否进入设备备份由发行隐私说明决定。
- 项目不集成第三方遥测 SDK；若以后新增，必须重新进行产品与隐私评审。

## 8. 内容与用户责任

- 应用不内置未经授权内容源，不运营公共源目录。
- 安装源前提示用户仅访问其有权访问的内容，并遵守源站条款和当地法律。
- 不实现绕过登录、付费、验证码、DRM 或地区访问控制的专用 API。
- 源若返回受保护内容，不改变应用的技术沙箱要求，也不代表应用认可其合法性。

## 9. 发行能力矩阵

| 能力 | Android 自签/GitHub | Google Play | iOS 自签/允许渠道 | iOS App Store |
|---|---:|---:|---:|---:|
| 导入本地 `.js` | 是 | 需政策评审 | 是 | 默认否 |
| 从 HTTPS URL 下载并加载 `.js` 本地副本 | 是 | 需严格沙箱与政策评审 | 视渠道 | 默认否 |
| 从 URL 安装 `.msrc` | 是 | 仅严格沙箱与政策合规 | 视渠道 | 默认否 |
| 未签名源 | 用户确认 | 默认禁用 | 用户确认 | 否 |
| 签名源仓库 | 是 | 可选、用户主动配置 | 视渠道 | 仅数据规则方案评估 |
| 本地文件阅读 | 是 | 是 | 是 | 是 |
| 内置测试/合法源 | 是 | 是 | 是 | 是 |

Google Play 当前禁止从 Play 之外下载 DEX/JAR/原生代码；解释型 JavaScript 并非一概禁止，但不得形成违反 Play 政策的能力，参见 [Google Play Developer Programme Policy：Device and network abuse](https://support.google.com/googleplay/android-developer/answer/16070163?hl=en-GB_in)。

Apple App Review Guideline 2.5.2 限制下载、安装或执行会引入或改变应用功能的代码，参见 [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)。因此 App Store 构建默认不启用用户下载 JavaScript 源；若未来尝试数据化、声明式规则方案，必须作为独立 ADR 和审核验证任务，不能仅靠改名规避规则。

## 10. 安全发布门槛

- JS 无限循环、内存炸弹和深递归能被硬终止；
- SSRF、重定向逃逸、DNS rebinding 和私网访问测试全部通过；
- 包解压路径穿越、ZIP bomb 和签名篡改测试全部通过；
- 模糊测试未发现可复现的宿主崩溃或越界；
- 日志和诊断包扫描不含测试 Cookie/Token；
- 渠道二进制能力与公开说明一致；
- 第三方依赖清单、许可证和已知漏洞检查完成。
