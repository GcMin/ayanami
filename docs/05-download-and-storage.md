# 下载与文件存储

## 1. 目标

下载系统必须面对源失效、签名 URL 过期、网络切换、应用退出、系统回收、磁盘不足和单页损坏。队列状态以 SQLite 为准，平台后台任务是执行器，不是唯一事实来源。

## 2. 文件布局

所有相对路径由宿主生成，不使用源提供的文件名作为路径：

```text
app-content/
  sources/
    <source-id>/<version>/package.msrc
  manga/
    <manga-uuid>/
      metadata.json
      cover/<hash>.<ext>
      chapters/
        <chapter-uuid>/
          chapter.json
          pages/
            000000-<hash-prefix>.<ext>
  cache/
    images/
    source-responses/
  temp/
    downloads/<task-uuid>/
  quarantine/
```

数据库只保存相对路径。任何删除、移动和清理操作都先解析并验证最终绝对路径仍在应用管理目录内。

## 3. 入队

`EnqueueChapterDownload`：

1. 校验章节和源可用性；
2. 估算空间，未知时使用保守阈值；
3. 复用同章节活动任务，避免重复；
4. 快照用户约束和优先级；
5. 写入任务后再通知平台调度器；
6. UI 观察数据库状态。

批量下载为多个章节任务的逻辑分组，不创建不可恢复的巨型事务。

### 3.1 从书架批量下载

书架通过长按漫画卡片或点击“批量选择”进入选择模式。选择一个或多个书架项后，底部操作栏提供“下载”。

下载范围：

```text
未下载章节（默认）
全部章节
每部漫画最新 N 章
逐部选择章节
```

创建流程：

1. 以稳定 `libraryEntryId` 获取所选作品，忽略已被移出书架的失效项；
2. 使用各作品的首选来源刷新或读取可接受的新鲜章节快照；
3. 根据范围排除已完成章节，复用已存在的活动任务；
4. 生成确认摘要：漫画数、待下载章节数、已知/未知大小、仅 Wi-Fi 等约束和剩余空间；
5. 用户确认后创建 `DownloadBatch`，再逐章幂等创建 `DownloadTask`；
6. 返回书架或进入下载页，均不影响后台队列继续执行。

取消确认不创建任务。某部漫画的源已禁用、删除或章节刷新失败时，在确认页把该漫画列为不可加入批次，其他漫画仍可继续。

批次状态按子任务汇总为 `queued`、`running`、`paused`、`partiallyCompleted`、`completed`、`failed` 或 `cancelled`。暂停/继续/取消批次只批量作用于仍可变更的子任务，不回滚已经完成的章节。

## 4. 页面下载流程

```text
读取 Page 描述
  -> 必要时调用 resolvePageRequest
  -> 校验最终 URL 与 Header
  -> 下载到 .part
  -> 校验状态码、MIME、大小和可解码性
  -> 计算 SHA-256
  -> 原子移动到正式路径
  -> 事务写入 LocalFile 与 DownloadItem
```

- 服务器支持 Range 时可续传；ETag/Last-Modified 不一致则丢弃旧分片重下。
- 不支持 Range 时以页为最小恢复单位。
- HTML 错误页伪装成图片必须通过 MIME 和解码探测拦截。
- 重试签名 URL 前先重新调用源解析函数。

## 5. 并发与重试

建议默认值：

| 项目 | 默认 |
|---|---:|
| 同时下载章节 | 2 |
| 单章节并发页 | 3 |
| 单页自动尝试 | 3 次 |
| 退避 | 1、3、10 秒并加随机抖动 |
| 最低剩余空间 | 512 MiB 或用户设置的更高值 |

HTTP 4xx 默认不重试；`408`、`429` 和签名过期可按响应和源能力处理。HTTP 5xx、DNS 和临时网络错误可重试。永久 Schema 错误直接失败。

用户暂停必须阻止新请求并尽快取消正在进行的请求；已验证页面保留。取消默认保留已完成页面供再次下载复用，用户可选择彻底删除。

## 6. 平台执行

### Android

- 使用 WorkManager 表达持久任务和网络/充电约束。
- 长任务按平台要求使用合规的前台执行方式和通知。
- Worker 可重复执行，必须幂等，并在停止信号到达时保存状态。
- 不承诺准确开始时间；系统约束满足后尽快执行。

### iOS

- 图片传输使用 background `URLSession`。
- 系统可在应用挂起时继续传输，但调度和唤醒时机由系统决定。
- JS 页面解析通常需要应用活动时间，因此先在前台解析页面清单，再提交可独立下载的 URL；过期 URL 需要用户重新打开应用恢复。
- 不用无限后台执行假设设计队列。

## 7. 缓存与正式下载

> 当前产品迭代按 ADR-015 支持当前章节全量预加载。预加载内容仍属于可清理缓存，只有用户主动下载后才进入正式下载目录并计入离线完成。

缓存可按 LRU/容量清理；正式下载只有用户操作或明确存储管理策略才能删除。

阅读器当前章节的后续页缓存使用滑动窗口：默认缓存当前页之后 5 页，用户可设置为关闭或 1–20 页。窗口只调度同一章节页面，优先级低于当前页和正式下载。

| 类型 | 是否可自动清理 | 是否计入离线完成 |
|---|---|---|
| 内存解码缓存 | 是 | 否 |
| 在线图片磁盘缓存 | 是 | 否 |
| `.part` 临时文件 | 超期后是 | 否 |
| 完成的章节文件 | 否 | 是 |
| 隔离文件 | 用户确认或超期策略 | 否 |

同一内容哈希可在内部去重，但删除引用时必须做引用计数，不能因一个章节删除而破坏另一个章节。

缓存页具备 `sourceId`、`chapterId`、`pageIndex`、请求版本/图片哈希、大小和最后访问时间。正式下载命中已验证缓存时可以原子提升或复用该文件；提升成功前仍按缓存处理，不能先把章节标记为离线完成。

## 8. 完整性与修复

- 章节完成条件：页面清单存在、索引连续、每页均有 `ready` 文件且可读取。
- 应用启动时进行轻量协调：数据库活动任务、平台任务和临时目录三方对账。
- 设置页提供深度扫描：检查丢失文件、孤儿文件、哈希异常和损坏图片。
- 修复操作不自动访问未启用源；需要重新下载时提示用户。

## 9. 删除语义

- 删除一个章节：取消相关任务，删除数据库引用，再删除解析后确认位于章节目录的文件。
- 删除一部漫画下载：逐章节执行，不删除书架和进度，除非用户另选。
- 清空缓存：不得触及正式下载目录。
- 卸载源：不得级联删除正式内容。

## 10. 验收场景

- 下载过程中杀进程并重启，可恢复且不重复已完成页。
- Wi-Fi 切换移动网络时遵循约束并暂停。
- URL 过期、服务器忽略 Range、磁盘写满和图片伪装 HTML 都返回正确错误。
- 两次点击下载同一章节只产生一个活动任务。
- 清理缓存、删除源和数据库迁移都不误删正式下载。
