# 实施路线图

路线图按 Android 可验收纵向闭环排序。当前目标不是先把所有底层抽象雕成艺术品，而是尽快完成“漫画源 -> 搜索 -> 详情 -> 书架 -> 阅读 -> 下载”的完整链路。

## M0：整理现有原型

交付：

- 首页调整为“书架 / 漫画源 / 设置”三个一级入口；
- 书架作为默认首页；
- 将现有 `lib/main.dart` 中原型按功能逐步拆分；
- 建立 `SourceRuntimeAdapter` 与 `ContentSourcePort` 边界；
- 保留现有 `flutter_js` + 漫蛙源作为验证实现；
- 补充基础单元测试和 Android 构建 CI。

退出条件：三个一级入口稳定；现有 JS 搜索、详情、章节和阅读链路没有因重构失效。

## M1：JS 漫画源插件化

交付：

- 漫画源页；
- 已安装源列表；
- 本地 `.js` 导入；
- HTTPS URL 添加 `.js`；
- Manifest 解析；
- `sourceApiVersion` 检查；
- 域名权限确认；
- 启用、禁用、删除；
- 源级错误状态；
- Source Runtime 超时与异常隔离；
- Host HTTP API；
- HTML/JSON 解析能力；
- 源级 Cookie/Storage 隔离。

退出条件：至少两个测试 JS 源可同时安装和启用，一个源失效不会影响另一个源或整个应用。

## M2：漫画源浏览与搜索

交付：

- 单源主页；
- 单源搜索；
- 多源聚合搜索；
- `getPopular`、`getLatest`、`getFilters` 可选能力；
- 搜索结果显示来源；
- `(sourceId, sourceMangaId)` 稳定路由；
- 详情和章节只回调产生结果的同一源；
- 搜索取消、单源重试和迟到结果丢弃。

退出条件：两个源同时搜索时，一个源超时仍可查看另一个源结果；点击结果不会再次执行关键词搜索。

## M3：书架与阅读器正式化

交付：

- SQLite/Drift 书架数据；
- `LibraryEntry` 持久化；
- 加入/移出书架；
- 阅读历史；
- 未读数量；
- 章节刷新；
- 阅读进度恢复；
- 四种阅读方向；
- 页面适应模式；
- 图片预加载和缓存；
- 源被删除后仍可查看书架快照和已下载内容。

退出条件：杀死应用并重启后，书架、最后章节和页码均正确恢复。

## M4：下载与离线阅读

交付：

- Android WorkManager；
- 单章下载；
- 多章下载；
- 书架批量下载；
- 暂停、继续、取消和重试；
- 下载数据库状态；
- 原子文件写入；
- 缓存与正式下载分离；
- 空间检查与失败恢复。

退出条件：下载中杀进程、断网和重新联网后任务能够恢复；完成下载的章节可断网阅读。

## M5：源分发与安全增强

交付：

- `.msrc` 包格式；
- Manifest 与脚本一致性校验；
- SHA-256；
- 包签名状态；
- 更新与回滚；
- 权限扩大重新确认；
- 源诊断日志；
- SSRF、路径穿越、资源炸弹和恶意脚本测试。

`.msrc` 不再阻塞前面的 Android MVP。先让 JS 插件机制真正好用，再给它穿防弹衣，比反过来更符合软件工程而不是祭祀活动。

## M6：发行

交付：

- GitHub Release APK；
- Android 自签构建；
- 隐私说明；
- 开源许可证；
- 数据导出/备份方案评估；
- 真机性能测试。

## 后续候选

- OCR；
- AI 翻译；
- 内容站登录；

- 自动同作品识别；
- 桌面端。

## 当前开发优先级

```text
P0 首页三 Tab
P0 漫画源页
P0 JS 源安装/启停
P0 单源搜索和详情
P1 多源聚合搜索
P1 SQLite 书架
P1 阅读进度
P2 WorkManager 下载
P2 .msrc 与签名
```

下一阶段不需要先重写整个 JS Runtime。应先把当前 `flutter_js` 实现包装到 `SourceRuntimeAdapter` 后面，完成产品闭环，再替换底层运行时。
